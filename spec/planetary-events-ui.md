# Feature Specification: Поиск и визуализация планетарных событий

**Feature File**: `spec/planetary-events-ui.md`

**Status**: Accepted

**Input**: Основной пользовательский сценарий «Поиск и визуализация планетарных событий»: выбор типа астрономического явления, выбор планет-участников, указание горизонта прогноза, валидация, блокировка повторной отправки, состояния загрузки/успеха/пустого ответа/ошибки расчёта и интеграция с перемоткой времени симуляции на 3D-орбите по макетам из docs/mockups/ (validation.png, load.png, succes.png, empty.png, error.png).

---

## 1. User Scenarios & Testing *(mandatory)*

### User Story 1 - Настройка параметров и поиск планетарного события (Priority: P1)

Как исследователь космоса или пользователь симулятора Солнечной системы, я хочу задавать тип астрономического явления (Соединение, Противостояние, Парад планет), выбирать минимум 2 планеты-участника и указывать горизонт прогноза в днях, чтобы находить ближайшие редкие астрономические конфигурации и визуализировать их на орбите.

- **Acceptance Scenario 1.1 (Значения по умолчанию и структура формы)**:
  Given панель поиска планетарных событий открыта,
  When пользователь просматривает форму,
  Then переключатель «Тип явления» (`SelectButton`) по умолчанию имеет значение «Соединение» (варианты: «Соединение», «Противостояние», «Парад планет»),
  And список участников отображает доступные планеты с помощью компонентов PrimeVue (например, `ToggleButton`),
  And поле «Горизонт прогноза» представлено компонентом `InputNumber` с допустимым диапазоном от 1 до 3650 дней (без белых системных браузерных стрелочек/spinners),
  And у всех полей формы присутствуют связанные `<label>` (`for` / `id`).

- **Acceptance Scenario 1.2 (Успешный поиск и отображение результата - succes.png)**:
  Given выбраны корректные параметры:
    - Тип явления: «Соединение» (или «Противостояние» / «Парад планет»)
    - Участники: выбрано 2 или более планеты (например, Земля и Марс; для парада планет — 3 или более)
    - Горизонт прогноза: числовое значение в диапазоне от 1 до 3650 дней,
  When пользователь нажимает кнопку «Найти событие» (`Button`) или нажимает клавишу `Enter`,
  Then запускается асинхронный расчёт события через API `searchPlanetaryEvents(params)`,
  And на время ожидания кнопка переходит в состояние `loading` / `disabled`,
  And под формой отображаются скелетоны PrimeVue `Skeleton` (состояние load.png),
  And при успешном нахождении события под формой отображается карточка PrimeVue `Card` со сведениями:
    - заголовок события («Найдено», тип события),
    - угловое расстояние между ними (Δθ),
    - дата события («Целевая дата»),
    - смещение времени («Смещение времени»),
  And в карточке присутствует кнопка PrimeVue `Button` «Показать на орбите».

- **Acceptance Scenario 1.3 (Перемотка времени на дату события)**:
  Given в результате успешного поиска отображается карточка с найденным событием,
  When пользователь нажимает кнопку «Показать на орбите»,
  Then время симуляции перематывается на точную дату и время найденного события,
  And позиции планет на 3D-сцене `SolarScene` обновляются в соответствии с вычисленной конфигурацией.

## 2. User Scenarios: Состояния сценария и обработка ошибок

### User Story 2 - Валидация полей формы (validation.png) (Priority: P1)

Как пользователь, я хочу получать наглядные и понятные сообщения об ошибках валидации при некорректном заполнении формы, чтобы быстро исправить введённые параметры.

- **Acceptance Scenario 2.1 (Валидация количества выбранных планет)**:
  Given в списке участников выбрано меньше 2 планет (0 или 1 планета; либо меньше 3 для парада планет),
  When пользователь пытается отправить форму (или кнопка отправки анализирует состояние формы),
  Then асинхронный расчёт не отправляется,
  And под списком участников выводится понятное сообщение об ошибке валидации:
    `«Выберите минимум 2 планеты для расчёта»` (или минимум 3 для парада планет).

- **Acceptance Scenario 2.2 (Валидация горизонта прогноза)**:
  Given поле «Горизонт прогноза» оставлено пустым, либо введено значение меньше 1, либо больше 3650 дней,
  When выполняется отправка формы,
  Then асинхронный расчёт не отправляется,
  And под полем ввода выводится понятное сообщение об ошибке валидации:
    `«Укажите горизонт прогноза от 1 до 3650 дней»`.

### User Story 3 - Загрузка, пустой результат и ошибка (load.png, empty.png, error.png) (Priority: P1)

Как пользователь, я хочу быть защищённым от повторных кликов во время долгих расчётов и видеть однозначную обратную связь для каждого исхода (загрузка, пустой результат, ошибка).

- **Acceptance Scenario 3.1 (Загрузка и предотвращение дублирующих расчётов - load.png)**:
  Given форма заполнена валидно и запущен асинхронный расчёт `searchPlanetaryEvents(params)`,
  When расчёт выполняется (искусственная задержка ~350 мс),
  Then кнопка «Найти событие» переходит в состояние `loading` / `disabled`,
  And двойной клик или повторное нажатие клавиши `Enter` не создают второй запрос,
  And под формой отображаются плейсхолдеры PrimeVue `Skeleton`.

- **Acceptance Scenario 3.2 (Пустой результат поиска - empty.png)**:
  Given расчёт завершился успешно, но за указанный горизонт дней событий выбранного типа не найдено,
  When сервис возвращает статус ненахождения,
  Then отображается аккуратная заглушка:
    `«За указанный период таких явлений не найдено. Попробуйте увеличить горизонт прогноза»`.

- **Acceptance Scenario 3.3 (Ошибка расчёта или сбой API - error.png)**:
  Given асинхронный расчёт завершился сбоем (ошибка вычислений, сетевой сбой или отклонение промиса),
  When промис отклоняется или возвращается ошибка,
  Then все выбранные планеты, тип явления и число дней сохраняются в форме без изменений,
  And отображается баннер PrimeVue `Message` (`severity="error"`) с текстом ошибки и кнопкой повтора («Повторить попытку»),
  And кнопка отправки возвращается в исходное состояние.

### User Story 4 - Доступность и адаптивность интерфейса (Priority: P2)

Как пользователь с клавиатурным управлением или пользователь мобильного устройства, я хочу удобно взаимодействовать с формой на экранах шириной от 375px и управлять всеми элементами без мыши.

- **Acceptance Scenario 4.1 (Связанные лейблы и ARIA)**:
  Given форма поиска планетарных событий отображается в интерфейсе,
  When разметку анализирует браузер или скринридер,
  Then у всех полей ввода присутствуют связанные теги `<label>` с корректными атрибутами `for` / `id`,
  And группы переключателей снабжены доступными именами (`aria-label` / `aria-labelledby`).

- **Acceptance Scenario 4.2 (Управление с клавиатуры и фокус)**:
  Given пользователь взаимодействует с панелью только с клавиатуры,
  When пользователь нажимает `Tab` / `Shift+Tab`,
  Then фокус последовательно перемещается между интерактивными элементами (SelectButton, ToggleButton планет, InputNumber, кнопки «Найти событие», «Показать на орбите», кнопки повтора и закрытия панели),
  And каждый интерактивный элемент имеет отчётливо видимый индикатор `:focus-visible`,
  And выбор планет и переключение типа осуществляются клавишами `Space` / стрелками / `Enter`,
  And отправка формы инициируется нажатием `Enter` в числовом поле ввода,
  And нажатие `Escape` закрывает панель.

- **Acceptance Scenario 4.3 (Адаптивность для экранов шириной 375px)**:
  Given ширина области просмотра составляет 375px (мобильный экран),
  When отображается панель поиска и карточка результата,
  Then элементы формы, кнопки выбора планет и карточка события корректно переносятся, не вызывают горизонтальной прокрутки страницы и сохраняют минимальную область клика (touch target).

## 3. Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Поле «Тип явления» MUST быть реализовано с помощью компонента PrimeVue `SelectButton` с опциями: «Соединение», «Противостояние», «Парад планет». Значение по умолчанию MUST быть «Соединение».
- **FR-002**: Выбор планет-участников MUST производиться с использованием компонентов PrimeVue (`ToggleButton`).
- **FR-003**: Система MUST требовать выбор как минимум 2 планет-участников (или 3 для парада планет). Если условие нарушено, при попытке отправки расчёт не отправляется и выводится сообщение об ошибке: `«Выберите минимум 2 планеты для расчёта»` (или 3 для парада планет).
- **FR-004**: Поле «Горизонт прогноза» MUST быть обязательным полем на базе PrimeVue `InputNumber` с допустимым диапазоном значений от 1 до 3650 дней.
- **FR-005**: При пустом значении или выходе за диапазон `[1, 3650]` система MUST отображать ошибку валидации: `«Укажите горизонт прогноза от 1 до 3650 дней»` и блокировать запуск расчёта.
- **FR-006**: У поля «Горизонт прогноза» (`InputNumber`) системные стрелочки браузера (spinners) MUST быть скрыты, оформление поля MUST соответствовать тёмному стилю PrimeVue.
- **FR-007**: При клике на кнопку «Найти событие» или нажатии клавиши `Enter` система MUST запускать асинхронный расчёт через `searchPlanetaryEvents(params)` с искусственной задержкой (~350 мс). На время расчёта кнопка отправки MUST переходить в состояние `loading` / `disabled`, а повторные клики и нажатия `Enter` MUST блокироваться.
- **FR-008**: На время ожидания завершения расчёта область результатов под формой MUST отображать плейсхолдеры PrimeVue `Skeleton`.
- **FR-009**: При успешном обнаружении события система MUST отображать карточку PrimeVue `Card`, содержащую:
  - статус («Найдено»),
  - минимальное угловое расстояние между телами (Δθ),
  - заголовок события,
  - целевую дату события,
  - смещение времени,
  - кнопку PrimeVue `Button` «Показать на орбите».
- **FR-010**: При клике на кнопку «Показать на орбите» время симуляции MUST перематываться на дату события с немедленным обновлением орбитальных позиций тел на 3D-сцене `SolarScene`.
- **FR-011**: Если за указанный горизонт дней событий не найдено, система MUST отображать понятное сообщение: `«За указанный период таких явлений не найдено. Попробуйте увеличить горизонт прогноза»`.
- **FR-012**: При ошибке расчёта или сбое API:
  - все выбранные пользователем параметры (тип явления, планеты, горизонт прогноза) MUST сохраняться без изменений,
  - сверху или под формой MUST отображаться баннер PrimeVue `Message` (`severity="error"`) с описанием ошибки и кнопкой «Повторить попытку».
- **FR-013**: В интерфейсе НЕ ДОЛЖНО присутствовать отладочного блока переключения состояний — состояния переключаются автоматически от действий пользователя и ответов асинхронного сервиса.
- **FR-014**: У всех полей формы MUST быть связанные теги `<label>` (`for` / `id`). Вся панель MUST полноценно управляться с клавиатуры (`Tab`, `Space`, `Enter`, `Escape`) с заметным индикатором `:focus-visible`.
- **FR-015**: Интерфейс панели MUST оставаться удобным и полностью функциональным на экранах шириной от 375px без появления паразитной горизонтальной прокрутки.
- **FR-016**: Запрещено использование нативных тегов `<button>`, `<input>`, `<select>`. Весь UI MUST строиться исключительно на компонентах PrimeVue (тема Aura в тёмном режиме): `SelectButton`, `ToggleButton`, `InputNumber`, `Button`, `Card`, `Skeleton`, `Message`.

## 4. Data Models & API Contract

```typescript
export type PlanetaryEventType = 'conjunction' | 'opposition' | 'parade';

export interface PlanetaryEventFilter {
  eventType: PlanetaryEventType;
  planetIds: string[];
  forecastDays: number;
  startTime?: number;
}

export interface PlanetaryEventResult {
  status: 'FOUND' | 'NOT_FOUND' | 'ERROR';
  eventType: PlanetaryEventType;
  participatingPlanets: string[];
  time: number | null;
  minAngularDifferenceDeg: number;
  targetDate?: string;
  title?: string;
  errorCode?: string;
  errorMessage?: string;
}

export interface PlanetaryEventCalculationResponse {
  success: boolean;
  event?: PlanetaryEventResult | null;
  error?: string;
}
```

## 5. Success Criteria *(mandatory)*

- **SC-001**: При любых некорректных параметрах (менее 2 планет, горизонт вне 1..3650 или пуст) отображаются регламентированные сообщения об ошибках под полями, и расчёт не запускается.
- **SC-002**: Во время расчёта полностью исключены параллельные дублирующие вызовы от повторных кликов или нажатий `Enter`.
- **SC-003**: При возникновении ошибки пользовательские параметры не сбрасываются, а кнопка «Повторить попытку» позволяет сразу перезапустить расчёт.
- **SC-004**: Нажатие кнопки «Показать на орбите» мгновенно синхронизирует время симуляции и трёхмерное положение планет в `SolarScene`.
- **SC-005**: 100% интерактивных элементов доступны для управления с клавиатуры с видимым индикатором `:focus-visible`, а разметка корректно отображается на экране шириной 375px.
