# Feature Specification: Добавление и управление пользовательскими небесными телами

**Feature File**: `spec/custom-bodies-ui.md`

**Status**: Draft

**Input**: Пользовательский сценарий создания и управления пользовательскими небесными телами (планеты, астероиды, кометы) через модальную форму и список с интеграцией в 3D-сцену `SolarScene` и PrimeVue UI.

---

## 1. User Scenarios & Testing *(mandatory)*

### User Story 1 - Создание пользовательского небесного тела через форму (Priority: P1)

Как исследователь космоса или пользователь симулятора Солнечной системы, я хочу открывать модальное окно добавления нового небесного тела, указывать его название, тип, радиус орбиты и радиус объекта, и отправлять форму, чтобы объект сохранялся в системе и визуализировался на орбите в 3D-сцене `SolarScene`.

- **Acceptance Scenario 1.1 (Открытие модального окна и значения по умолчанию)**:
  Given пользователь инициирует добавление объекта (кнопка создания),
  When открывается диалоговое окно (PrimeVue `Dialog`),
  Then фокус устанавливается на первое доступное поле формы,
  And поле «Тип тела» (`Select`) по умолчанию имеет значение «Планета»,
  And поля «Название тела», «Радиус орбиты» и «Радиус объекта» пусты,
  And форма готова к вводу.

- **Acceptance Scenario 1.2 (Успешное сохранение и отображение)**:
  Given форма заполнена валидными значениями:
    - Название: непустая строка («Новая Экзопланета»)
    - Тип: «Планета» (или «Астероид», «Комета»)
    - Радиус орбиты: от 0.3 до 50 а.е.
    - Радиус объекта: от 100 до 100 000 км,
  When пользователь нажимает кнопку сохранения или нажимает `Enter`,
  Then запускается асинхронный вызов `createCustomBody`,
  And во время запроса кнопка отправки переходит в состояние `loading`, отправка по `Enter` блокируется,
  And при успешном завершении модальное окно закрывается,
  And поля формы сбрасываются в исходное состояние,
  And новое небесное тело добавляется в список пользовательских объектов,
  And новое тело создаётся и отрисовывается на орбите в 3D-сцене `SolarScene`.

### User Story 2 - Валидация полей и обработка ошибок ввода (Priority: P1)

Как пользователь, я хочу получать мгновенную и однозначную валидацию каждого поля формы, чтобы не допустить создания небесных тел с некорректными астрономическими или интерфейсными параметрами.

- **Acceptance Scenario 2.1 (Валидация названия)**:
  Given поле «Название тела» (`InputText`) оставлено пустым или содержит строку только из пробелов,
  When пользователь пытается отправить форму или переводит фокус с поля,
  Then форма считается невалидной,
  And выводится ошибка валидации: `«Введите название небесного тела»`,
  And запрос на создание `createCustomBody` не отправляется.

- **Acceptance Scenario 2.2 (Валидация радиуса орбиты)**:
  Given поле «Радиус орбиты (а.е.)» (`InputNumber`) пустое, меньше 0.3 или больше 50,
  When выполняется валидация формы при отправке,
  Then выводится ошибка валидации: `«Укажите радиус орбиты от 0.3 до 50 а.е.»`,
  And отправка запроса блокируется.

- **Acceptance Scenario 2.3 (Валидация радиуса объекта)**:
  Given поле «Радиус объекта (км)» (`InputNumber`) пустое, меньше 100 или больше 100 000,
  When выполняется валидация формы при отправке,
  Then выводится ошибка валидации: `«Укажите радиус от 100 до 100 000 км»`,
  And отправка запроса блокируется.

---

### User Story 3 - Предотвращение дублирующих запросов и обработка ошибок API (Priority: P2)

Как пользователь, я хочу, чтобы при медленном соединении или ошибке на сервере интерфейс вёл себя предсказуемо, не допускал дублирующих отправок и сохранял введённые мной данные.

- **Acceptance Scenario 3.1 (Блокировка повторной отправки)**:
  Given пользователь отправил валидную форму и запрос `createCustomBody` находится в процессе выполнения (pending),
  When пользователь повторно кликает на кнопку отправки или нажимает `Enter`,
  Then кнопка отправки остаётся в состоянии `disabled` / `loading`,
  And повторный асинхронный запрос `createCustomBody` не генерируется.

- **Acceptance Scenario 3.2 (Обработка сбоя сохранения / API error)**:
  Given асинхронный вызов `createCustomBody` завершается с ошибкой (reject / API error),
  When промис отклоняется,
  Then модальное окно остаётся открытым,
  And все введённые пользователем данные во всех полях формы сохраняются без изменений,
  And сверху формы отображается баннер ошибки (PrimeVue `Message`) с понятным текстом и кнопкой повторной отправки,
  And кнопка отправки возвращается в активное состояние для повторной попытки.

### User Story 4 - Управление списком пользовательских тел (Priority: P2)

Как пользователь, я хочу видеть список созданных объектов с состояниями загрузки, отсутствия данных и действий фокусировки/удаления, чтобы взаимодействовать с созданными объектами в 3D-симуляции.

- **Acceptance Scenario 4.1 (Состояние загрузки)**:
  Given пользовательские тела загружаются или инициализируются,
  When список ожидает данных,
  Then отображаются плейсхолдеры загрузки (PrimeVue `Skeleton`).

- **Acceptance Scenario 4.2 (Пустой список)**:
  Given в системе нет созданных пользовательских объектов,
  When список отображается пользователю,
  Then отображается информационное пустое состояние с текстом: `«Пользовательских объектов на орбите пока нет»`.

- **Acceptance Scenario 4.3 (Фокусировка камеры и удаление)**:
  Given в списке отображаются добавленные небесные тела,
  When пользователь нажимает действие «Сфокусировать» на конкретном объекте,
  Then камера `SolarScene` плавно центрируется на выбранном пользовательском теле,
  And When пользователь нажимает действие «Удалить» на объекте,
  Then объект удаляется из списка пользовательских тел и удаляется из 3D-сцены `SolarScene`.

---

### User Story 5 - Доступность и управление с клавиатуры (Priority: P3)

Как пользователь, использующий клавиатуру или скринридер, я хочу полноценно взаимодействовать со всеми элементами интерфейса без использования мыши.

- **Acceptance Scenario 5.1 (Связанные лейблы)**:
  Given модальное окно создания тела открыто,
  When скринридер или браузер анализирует форму,
  Then каждое поле ввода имеет связанный тег `<label>` с соответствующим атрибутом `for` / `id`.

- **Acceptance Scenario 5.2 (Клавиатурная навигация и индикаторы)**:
  Given модальное окно или список тел активны,
  When пользователь перемещается с помощью `Tab` и `Shift+Tab`,
  Then фокус последовательно переходит по интерактивным элементам с чётким индикатором `:focus-visible`,
  And нажатие `Escape` закрывает модальное окно (если нет блокирующей операции),
  And нажатие `Enter` в полях формы инициирует отправку.

## 2. Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Поле «Название тела» MUST быть обязательным текстовым полем на базе PrimeVue `InputText`. Строка из одних пробелов считается невалидной. При непрохождении валидации система MUST отображать ошибку: `«Введите название небесного тела»`.
- **FR-002**: Поле «Тип тела» MUST быть выпадающим списком PrimeVue `Select` с вариантами: «Планета», «Астероид», «Комета». Значение по умолчанию MUST быть «Планета».
- **FR-003**: Поле «Радиус орбиты (а.е.)» MUST быть обязательным числовым полем PrimeVue `InputNumber` с допустимым диапазоном `[0.3, 50]`. При выходе за диапазон или отсутствии значения MUST отображаться ошибка: `«Укажите радиус орбиты от 0.3 до 50 а.е.»`.
- **FR-004**: Поле «Радиус объекта (км)» MUST быть обязательным числовым полем PrimeVue `InputNumber` с допустимым диапазоном `[100, 100000]`. При нарушении диапазона или отсутствии значения MUST отображаться ошибка: `«Укажите радиус от 100 до 100 000 км»`.
- **FR-005**: Во время выполнения асинхронного сохранения `createCustomBody` система MUST блокировать кнопку отправки и подавлять повторные отправки по `Enter` (состояние `disabled` / `loading`), предотвращая параллельные запросы.
- **FR-006**: При успешном выполнении `createCustomBody` система MUST:
  - закрыть модальное окно `Dialog`,
  - сбросить значения всех полей формы в исходное состояние,
  - добавить созданный объект в список пользовательских тел,
  - вызвать создание и отрисовку соответствующего 3D-меша на орбите в `SolarScene`.
- **FR-007**: При ошибке асинхронного сохранения `createCustomBody` (API error):
  - модальное окно MUST оставаться открытым,
  - все введённые пользователем значения MUST сохраняться без изменений,
  - сверху формы MUST отображаться компонент PrimeVue `Message` с понятным описанием ошибки и возможностью повторить отправку.
- **FR-008**: Список пользовательских небесных тел MUST поддерживать три визуальных состояния:
  - `Loading`: отображение индикаторов скелетной загрузки (PrimeVue `Skeleton`),
  - `Empty`: отображение сообщения `«Пользовательских объектов на орбите пока нет»`,
  - `Populated`: отображение карточек/элементов тел с действием фокусировки камеры в `SolarScene` и действием удаления объекта.
- **FR-009**: Все поля ввода MUST иметь связанные `<label>` (`id` / `for`). Весь сценарий создания и управления MUST быть доступен для навигации с клавиатуры (`Tab`, `Enter`, `Escape`) с видимым индикатором `:focus-visible`.
- **FR-010**: Запрещено использование нативных кастомных `<button>`, `<input>`, `<select>` и самописных модальных окон. Весь UI MUST строиться на компонентах PrimeVue (тема Aura в тёмном режиме): `Button`, `InputText`, `InputNumber`, `Select`, `Dialog`, `Card`, `Message`, `Skeleton`, `SelectButton`.

### Data Models & Contracts

```typescript
export type CustomBodyType = 'planet' | 'asteroid' | 'comet';

export interface CustomBodyInput {
  name: string;
  type: CustomBodyType;
  orbitRadiusAu: number;
  radiusKm: number;
}

export interface CustomCelestialBody extends CustomBodyInput {
  id: string;
  createdAt: number;
  color?: string;
}

export interface CreateCustomBodyResponse {
  success: boolean;
  data?: CustomCelestialBody;
  error?: string;
}
```

## 3. Success Criteria *(mandatory)*

- **SC-001**: Форма полностью валидирует граничные условия и выводит регламентированные тексты ошибок без перезагрузки страницы.
- **SC-002**: При возникновении сетевой ошибки или ошибки API данные формы не теряются, позволяя пользователю исправить ошибку или повторить отправку в один клик.
- **SC-003**: 100% интерактивных элементов доступны для навигации с клавиатуры с видимым кольцом фокуса `:focus-visible`.
- **SC-004**: Успешно созданное тело немедленно отображается как в списке, так и в 3D-пространстве `SolarScene`.
